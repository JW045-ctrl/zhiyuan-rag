# 知源项目术语表

这份术语表只解释知源已经使用或明确讨论过的概念。“需要掌握”表示当前阶段应能做出的判断，不要求一次学完所有底层原理。

## RAG（检索增强生成）

- **一句话解释：** 先从指定资料中找依据，再让大模型依据这些内容组织回答。
- **在知源中负责什么：** 把微积分课件、习题和答案与 AI 问答连接起来，并为回答提供可检查的来源。
- **目前需要掌握到什么程度：** 能区分“没有检索到”“检索到了但回答错了”和“引用不正确”三类问题。
- **属于哪一部分：** Dify 封装了主要流程；题目范围、可靠性标准和参数取舍需要你主动决策；Codex 生成测试与网站连接代码。

## LLM（大语言模型）

- **一句话解释：** 根据输入文字预测并生成后续文字的模型，例如当前计划使用的通义千问模型。
- **在知源中负责什么：** 把检索到的资料整理成中文解释，而不是决定真实引用来自哪里。
- **目前需要掌握到什么程度：** 知道它可能写出流畅但无依据的内容，所以必须配合检索、引用和拒答规则。
- **属于哪一部分：** 模型调用由 Dify 封装；选择哪个模型、可接受的价格和效果由你主动决策。

## Chunk（文本片段）

- **一句话解释：** 把长文档切成的较小文本块，便于逐块查找。
- **在知源中负责什么：** Dify 实际检索并返回的 `content` 通常就是某个片段的正文。
- **目前需要掌握到什么程度：** 理解片段太短可能缺少上下文，太长可能混入无关内容；当前最佳长度待评估。
- **属于哪一部分：** 切分由 Dify 封装，切分策略需要你根据评估结果主动决策。

## 父子分段

- **一句话解释：** 用较小的“子片段”精确查找，再把包含它的较大“父片段”交给模型阅读。
- **在知源中负责什么：** 这是未来可能改善检索精度与上下文完整性的切分方式，当前是否启用待确认。
- **目前需要掌握到什么程度：** 能理解“用小块找、用大块答”的基本取舍即可。
- **属于哪一部分：** 属于 Dify 可配置能力；是否使用必须由评估证据支持，是你需要主动决策的部分。

## Embedding（文本向量化）

- **一句话解释：** 把文字转换成一组数字，使意思接近的文字在数字表示上也更接近。
- **在知源中负责什么：** 让中文问题有机会找到英文课件中含义相近的片段。
- **目前需要掌握到什么程度：** 知道更换向量模型会影响检索结果，不能在记录基线时随意更换。
- **属于哪一部分：** 生成与存储流程由 Dify 封装；模型选择由你主动决策。

## 向量

- **一句话解释：** 一串按顺序排列的数字，在这里用来表示一段文字的大致含义。
- **在知源中负责什么：** 用于比较用户问题与课程片段在含义上的接近程度。
- **目前需要掌握到什么程度：** 不需要手算，只需知道它是检索的中间表示，不等于原文，也不保证答案正确。
- **属于哪一部分：** 由 Embedding 模型和 Dify 自动产生；业务是否接受其效果由你决策。

## 向量数据库

- **一句话解释：** 专门保存向量并快速寻找相近向量的存储系统。
- **在知源中负责什么：** 保存课程片段的数字表示，并为 Dify 返回相似片段。
- **目前需要掌握到什么程度：** 会确认服务是否运行、数据是否保留，并理解它不是课程原文的唯一备份。
- **属于哪一部分：** 由 Dify 的 Docker 部署封装；备份、容量和公开部署方案需要你决策。

## Weaviate

- **一句话解释：** 知源当前 Dify 部署所使用的一种向量数据库软件。
- **在知源中负责什么：** 存放知识库片段的向量，供检索流程查找。
- **目前需要掌握到什么程度：** 会检查容器状态，知道删除对应 Docker 数据卷会丢失已建立的索引；深入调优待评估。
- **属于哪一部分：** 主要是 Dify 部署的封装能力；数据保护和替换方案由你主动决策。

## 召回

- **一句话解释：** 根据问题从知识库找回一批可能相关的片段。
- **在知源中负责什么：** 决定模型作答前能看到哪些课件、习题或答案内容。
- **目前需要掌握到什么程度：** 能用期望文档命中率判断是否找到了应有资料。
- **属于哪一部分：** Dify 执行召回；评估召回好坏是测试脚本和你的人工复核共同完成的。

## Top K

- **一句话解释：** 每次检索最多保留得分最高的 K 个片段，例如 K 为 3 就最多取 3 个。
- **在知源中负责什么：** 控制进入回答环节的候选资料数量。
- **目前需要掌握到什么程度：** 知道太小可能漏资料，太大可能带入噪声；本轮只记录现状，不修改。
- **属于哪一部分：** Dify 中可配置；具体数值必须根据固定评估集由你决策。

## 相似度阈值

- **一句话解释：** 只有相似程度达到某个最低标准的片段才被保留。
- **在知源中负责什么：** 尝试过滤与问题关系较弱的课程片段。
- **目前需要掌握到什么程度：** 知道阈值过高可能漏检，过低可能误检；当前合理值待评估。
- **属于哪一部分：** Dify 中可配置，是需要用评估证据主动决策的参数。

## Rerank（重新排序）

- **一句话解释：** 对第一轮找出的候选片段再判断一次相关性，并重新排列顺序。
- **在知源中负责什么：** 可能把真正有用的片段提到前面；当前实际配置与收益待评估。
- **目前需要掌握到什么程度：** 能理解它增加一次判断，可能提升排序，也可能增加时间和费用。
- **属于哪一部分：** 可由 Dify 和外部排序模型封装；是否启用由你主动决策。

## Prompt（提示词）

- **一句话解释：** 给模型的任务说明，例如“只依据资料回答，资料不足时拒答”。
- **在知源中负责什么：** 约束回答范围、语气、引用说明和拒答行为。
- **目前需要掌握到什么程度：** 会读懂当前规则，并知道提示词只能降低风险，不能保证模型永不犯错。
- **属于哪一部分：** 在 Dify Chatflow 中配置；内容由你主动决策，Codex 可协助整理和测试。

## Chatflow

- **一句话解释：** Dify 中用可视步骤组织一次聊天请求的流程。
- **在知源中负责什么：** 串起用户问题、知识检索、资料不足判断和模型回答。
- **目前需要掌握到什么程度：** 能查看节点、发布版本并导出 DSL，不必现在开发 Dify 本身。
- **属于哪一部分：** 属于 Dify 封装能力；流程规则由你主动决策。

## DSL

- **一句话解释：** 用文本文件保存 Chatflow 结构和设置的可导入格式。
- **在知源中负责什么：** 让当前 Dify 流程能够备份、复盘和迁移，同时不包含真实密钥。
- **目前需要掌握到什么程度：** 会安全导出、确认不带密钥并放入版本管理；无需手写全部内容。
- **属于哪一部分：** Dify 生成，Git 保存；是否公开和如何审计由你决策。

## SSE（服务器发送事件）

- **一句话解释：** 服务器保持一条连接，按事件连续把回答片段发给浏览器。
- **在知源中负责什么：** 实现文字逐步出现，并在结尾发送真实引用与完成状态。
- **目前需要掌握到什么程度：** 能分辨回答增量、完成、错误和意外断流。
- **属于哪一部分：** Dify 提供上游流，Codex 生成的 Next.js 代码负责转发和解析；是否继续使用由你决策。

## API（程序接口）

- **一句话解释：** 两个程序按约定格式交换请求和结果的入口。
- **在知源中负责什么：** 浏览器调用 `/api/chat`，Next.js 再调用 Dify 的 `/chat-messages`。
- **目前需要掌握到什么程度：** 理解地址、请求方法、请求内容、响应和错误，不需要记住所有字段。
- **属于哪一部分：** Dify 提供外部 API，Codex 生成网站接口代码；公开权限由你决策。

## 服务端代理

- **一句话解释：** 浏览器不直接访问 Dify，而是让知源服务器代为请求并转回安全结果。
- **在知源中负责什么：** 隐藏 API Key、统一错误处理，并只把必要数据发给页面。
- **目前需要掌握到什么程度：** 知道密钥只在服务端读取，并会检查浏览器响应中没有密钥。
- **属于哪一部分：** 由 Codex 生成的 Next.js 代码实现；安全边界由你主动决策。

## Next.js

- **一句话解释：** 同时支持网页界面和服务端接口的 React 网站框架。
- **在知源中负责什么：** 提供 `/assistant` 页面和 `/api/chat` 服务端代理。
- **目前需要掌握到什么程度：** 会安装依赖、配置环境变量、启动、构建并查看基本错误；深入优化待需要时学习。
- **属于哪一部分：** 网站代码主要由 Codex 协助生成，产品行为和部署选择由你决策。

## PostgreSQL

- **一句话解释：** 一种保存结构化数据的数据库软件。
- **在知源中负责什么：** 当前主要供本地 Dify 保存应用配置、运行信息等数据；知源网站 v0.1 尚未把它作为自己的业务数据库。
- **目前需要掌握到什么程度：** 知道不能随意删除其 Docker 数据卷，并理解备份的重要性。
- **属于哪一部分：** 属于 Dify 部署组件；未来网站是否使用需要你主动决策。

## Redis

- **一句话解释：** 一种速度很快的临时数据与消息存储软件。
- **在知源中负责什么：** Dify 用它协调任务和消息；之前的同步问题曾出现 Redis 接收重试日志。
- **目前需要掌握到什么程度：** 会检查容器与日志，知道它异常可能影响 Dify 协作或后台任务。
- **属于哪一部分：** 属于 Dify 部署组件；运维和替换方案由你决策。

## Docker

- **一句话解释：** 把应用及其运行环境装进相互隔离的容器，便于在同一台电脑启动多个服务。
- **在知源中负责什么：** 本地运行 Dify、PostgreSQL、Redis、Weaviate 等组件。
- **目前需要掌握到什么程度：** 会安全启动、停止和查看状态；明确 `down -v` 可能删除数据卷，不能随意执行。
- **属于哪一部分：** 是 Dify 的运行基础；数据目录、备份和公开部署方式由你主动决策。

## JSON

- **一句话解释：** 用键和值记录结构化数据的纯文本格式。
- **在知源中负责什么：** 保存 RAG 测试题、每题结果、指标和部分 API 数据。
- **目前需要掌握到什么程度：** 能识别对象、数组、字符串和布尔值，并避免漏逗号或破坏引号。
- **属于哪一部分：** 测试与接口代码由 Codex 生成；字段含义和哪些数据可公开由你决策。

## JSON Schema

- **一句话解释：** 一份检查 JSON 必须有哪些字段、字段是什么类型的规则文件。
- **在知源中负责什么：** 约束 30 道测试题的结构，减少漏填或填错格式。
- **目前需要掌握到什么程度：** 能根据检查报错定位缺失字段，不必掌握全部规范。
- **属于哪一部分：** 由 Codex 生成并维护；必填业务信息由你主动决策。

## Git

- **一句话解释：** 记录文件每次变化并允许查看或恢复历史的版本管理工具。
- **在知源中负责什么：** 保存代码、文档、测试题和不含密钥的 Dify DSL，同时排除私密环境文件与课程原文。
- **目前需要掌握到什么程度：** 会看状态、确认提交范围、理解提交与推送不是一回事，并在推送前检查敏感内容。
- **属于哪一部分：** 工具本身独立于 Dify；Codex 可执行操作，是否提交和公开由你主动决策。

## README

- **一句话解释：** 放在项目入口处的使用说明文档。
- **在知源中负责什么：** 告诉新环境需要什么、怎样配置、启动、测试和了解安全边界。
- **目前需要掌握到什么程度：** 能按文档从空环境操作，并在流程变化后同步更新。
- **属于哪一部分：** 由 Codex 协助编写，你需要确认说明与自己的实际操作一致。

## 回归测试

- **一句话解释：** 修改后重复运行已有测试，确认原来能工作的功能没有被破坏。
- **在知源中负责什么：** 固定 RAG 题集比较检索与回答变化，代码测试检查 SSE、引用和数据格式。
- **目前需要掌握到什么程度：** 知道先记录基线、一次只改一个变量，再用同一批题重测。
- **属于哪一部分：** Codex 生成运行框架；题目质量、人工结论和改动顺序由你主动决策。

## 微调

- **一句话解释：** 用准备好的样本继续训练模型，使其更适合某类任务，而不是简单地把资料放入知识库。
- **在知源中负责什么：** 当前未使用，也不应把它与 RAG 检索混为一谈。
- **目前需要掌握到什么程度：** 知道微调通常不能代替实时引用课程资料，是否需要、成本和收益都待评估。
- **属于哪一部分：** 不是当前 Dify 流程的已验证能力；若未来考虑，属于你需要基于证据主动决策的方向。
